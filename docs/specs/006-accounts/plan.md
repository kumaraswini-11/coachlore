# 006: Accounts, the plan

How this repository builds [spec 006](spec.md).

## Builds on

- **Specs:** 000 (Vercel deploys, Sentry in the web app, CI), 001 (the
  shell, the states, `EmptyState`).
- **ADR 0006 pieces added here:** `apps/server` on Fastify 5 with
  `@fastify/type-provider-zod`; PostgreSQL; `packages/db` (Drizzle and
  drizzle-kit); `packages/auth` (Better Auth with the Discord provider);
  `packages/contracts`; pino; Sentry for Node; Testcontainers; hosting on
  the Oracle A1 VM with Coolify, a DuckDNS name and no domain ("Hosting").
- **ADR 0007:** every string from the dictionaries spec 001 sets up; the
  account keeps the person's language.
- Every version is the newest release at least two weeks old on the day the
  task adds it (AGENTS.md, "Versions"); shared ones go in the workspace
  catalog.

## Data model

Better Auth's four tables, generated into `packages/db/src/schema/auth.ts`
with its CLI for Drizzle and kept as generated, plus one field Better Auth
adds through its `additionalFields` option:

| Table          | Holds                                                                                                                                               |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `user`         | `id`, `name` (Discord display name), `image` (Discord avatar URL), `email` (see Decisions), `email_verified`, `language` (`en` or `hi`), timestamps |
| `session`      | `id`, `token`, `user_id`, `expires_at`, timestamps; `ip_address` and `user_agent` always null (see Decisions)                                       |
| `account`      | `id`, `user_id`, `provider_id` (`discord`), `account_id` (the Discord ID), timestamps; token columns null (see Decisions)                           |
| `verification` | short-lived values the sign-in flow needs (its `state` and PKCE verifier)                                                                           |

These four keep Better Auth's singular names; every table our specs add is
plural `snake_case`. Nothing else is stored by this spec. The Discord ID
lives in `account.account_id` and is what identifies a person across
sign-ins.

**Deletion and export are extensible.** `account/deletion.ts` holds two
lists: _blockers_ (each returns reasons the account can't be deleted yet)
and _anonymisers_ (each runs inside the deletion's transaction). 007 adds
the "only admin" blocker and the "A former coach" anonymiser;
`account/export.ts` holds exporters the same way. Each later spec that
stores something about a person adds one of each.

## API

All under `/api/v1/`, through the web app's proxy. Shapes in
`packages/contracts`.

| Method and path                | Who              | Does                                                                                                                                                                                                            |
| ------------------------------ | ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/v1/health`           | anyone, directly | `{ status: "ok" \| "degraded", db: "up" \| "down", draftLive: boolean }`; exempt from the origin guard so Coolify can call it; `draftLive` is false until 008 sets it, and the owner checks it before deploying |
| `GET /api/v1/me`               | signed in        | `{ id, name, image, discordId, language, createdAt, memberships: [] }` (007 fills `memberships`)                                                                                                                |
| `PATCH /api/v1/me`             | signed in        | `{ language }`: sets the account's language; the web app also sets the language cookie and reloads in it                                                                                                        |
| `GET /api/v1/me/export`        | signed in        | the JSON download, `Content-Disposition: attachment; filename="coachlore-data.json"`                                                                                                                            |
| `DELETE /api/v1/me`            | signed in        | 204 and every session ended; 409 problem details with `blockers: [{ league, reason }]` if blocked                                                                                                               |
| `POST /api/v1/realtime/ticket` | signed in        | `{ ticket, expiresAt }`: a one-minute, single-use ticket                                                                                                                                                        |
| `/api/auth/*`                  | as Better Auth   | sign in with Discord, the callback, sign out, the session                                                                                                                                                       |

- **Signed in** means a valid session cookie; otherwise 401 problem details.
- **Rate limits:** 20 requests a minute per client address on `/api/auth/*`
  and on `DELETE /api/v1/me`; 300 a minute elsewhere (spec 014 sets the
  final limits). The client address is `x-coachlore-client-ip`, trusted
  only with a valid `x-coachlore-origin` secret.
- **Problem details** for every error; field errors in `errors`.

**The ticket** is `base64url(payload).base64url(HMAC-SHA256(payload))` with
`payload = { userId, nonce, exp }`, signed with `TICKET_SECRET` using
`node:crypto`. Redeeming checks the signature, the expiry and that the
nonce hasn't been used; used nonces are kept in memory until they expire
(one server; see Decisions). 008 redeems tickets when a socket connects.

## Hosting and environments

| Variable                 | Where  | What                                                                                                                                           |
| ------------------------ | ------ | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `DATABASE_URL`           | server | PostgreSQL connection string; only `packages/db` reads it, so moving to Neon or any PostgreSQL is a change here (ADR 0006, the owner's call 4) |
| `BETTER_AUTH_SECRET`     | server | Better Auth's signing secret                                                                                                                   |
| `BETTER_AUTH_URL`        | server | the web app's address: `https://coachlore.vercel.app` (`http://localhost:3000` locally)                                                        |
| `DISCORD_CLIENT_ID`      | server | from the Discord application                                                                                                                   |
| `DISCORD_CLIENT_SECRET`  | server | from the Discord application                                                                                                                   |
| `ORIGIN_SECRET`          | both   | the proxy's shared secret, 32 random bytes or more; never `NEXT_PUBLIC_`                                                                       |
| `ORIGIN_SECRET_PREVIOUS` | server | set only while the secret is being changed; the guard accepts it too                                                                           |
| `TICKET_SECRET`          | server | signs real-time tickets                                                                                                                        |
| `SENTRY_DSN`             | server | Sentry's project for the server                                                                                                                |
| `PORT`, `LOG_LEVEL`      | server | defaults 4000 and `info`                                                                                                                       |
| `SERVER_ORIGIN`          | web    | `https://coachlore.duckdns.org` (`http://localhost:4000` locally); server-side only                                                            |

- **Local:** `docker compose up -d` starts PostgreSQL 18 on 5432;
  `bun run dev` starts the web app and the server through Turborepo; the
  Discord application lists `http://localhost:3000/api/auth/callback/discord`.
- **Production:** Coolify builds `apps/server/Dockerfile` from `main` on
  every push and serves it at `https://coachlore.duckdns.org` with a
  Let's Encrypt certificate; PostgreSQL is a Coolify database on the same
  VM, not exposed to the internet; backups go daily to an Oracle Object
  Storage bucket through its S3-compatible API, kept for 14 days.
- **Vercel** gets `SERVER_ORIGIN`, `ORIGIN_SECRET` and (from spec 008)
  `NEXT_PUBLIC_REALTIME_URL` for **Production only**: a preview has none, its proxy answers 404, and its league and
  account screens render fixtures. The Discord application lists
  `https://coachlore.vercel.app/api/auth/callback/discord`.
- **Function region:** Vercel's "default Function region is Washington,
  D.C., USA (iad1) for all new projects", and "You can set a new default
  region through your project's settings"
  ([regions](https://vercel.com/docs/functions/configuring-functions/region)).
  The project's region is set to the one nearest the VM's home region, so
  the proxy's hop is short; spec 014 measures it.
- **Turborepo:** strict environment mode passes only declared variables, so
  the server's `dev`, `test` and `start` tasks list theirs in `env`, and
  `passThroughEnv` for secrets that mustn't change the cache key.
- **Deploys:** Coolify's health check calls `/api/v1/health`, with a start
  period long enough for migrations. Coolify: "When application health
  checks are enabled, Traefik removes unhealthy containers from routing"
  ([health checks](https://coolify.io/docs/knowledge-base/health-checks)),
  so with rolling updates a new version takes traffic only once it's
  healthy. Before merging, the owner checks that `draftLive` is false.
- **Shutdown:** on SIGTERM the server stops accepting, runs its shutdown
  hooks (008 adds `io.close()`, 011 adds `boss.stop()`), lets Fastify's
  `close()` finish requests in flight, and exits; anything left after 10
  seconds is cut off.
- **Migrations:** forward-only and backward-compatible: a change adds or
  widens, and anything removed goes in a later change, once no running
  version reads it. A pull request that adds a migration says so in its
  description, and the owner takes a Coolify backup before merging it.
  pg-boss (spec 011) keeps its own schema and migrates it when it starts:
  its major version is pinned exactly, and an upgrade to a new major is its
  own pull request, with a backup taken first.
- **The secret:** generated with `openssl rand -base64 32`. To change it:
  set the new value as `ORIGIN_SECRET` and the old as
  `ORIGIN_SECRET_PREVIOUS` on the server, deploy, change Vercel's value,
  redeploy the web app, then remove `ORIGIN_SECRET_PREVIOUS`.
- **The machine:** Coolify's dashboard is reached only through an SSH
  tunnel (or from an allow-listed address) and has two-factor sign-in; SSH
  takes keys only; Ubuntu's unattended security updates are on; the VM's
  security list opens only 22, 80 and 443.
- **Backups:** a private Object Storage bucket, reached by a key that can
  reach only that bucket; 14 kept, so deleted data leaves backups within
  14 days.
- **A fallback name:** a second free DNS name for the VM, at a different
  free service, is set up with the first and listed in
  `apps/server/README.md`; switching is a change to `SERVER_ORIGIN`.
- **CSP** (`apps/web/next.config.ts`): `img-src` adds
  `https://cdn.discordapp.com` for avatars; `next/image` gets the same
  remote pattern.
- **A nonce CSP for signed-in pages:** Next.js's guide says you "must use dynamic
  rendering to add nonces", with a Proxy that "creates a unique
  nonce for the request" (the bundled `content-security-policy.md`).
  `proxy.ts`'s matcher includes the language: `/:lang/me` here (008 adds
  `/:lang/l/:path*`, 012 adds `/:lang/ask`),
  sets `script-src 'self' 'nonce-…' 'strict-dynamic'` without
  `'unsafe-inline'`, and passes the nonce on in `x-nonce`; these pages are
  dynamic already. The policy's `connect-src` also lists the server's
  `wss://` origin, from `NEXT_PUBLIC_REALTIME_URL` (spec 008 sets the
  value; until then it's left out). The static Dex keeps ADR 0003's policy:
  `next.config.ts`'s `headers()` excludes the routes the proxy covers
  (a `source` with a negative lookahead for them), so every page gets
  exactly one `Content-Security-Policy` header.
- **The language at sign-in:** a `databaseHooks.user.create.before` hook
  sets `language` from the language cookie (English when it's missing).
  After sign-in, the web app sets the cookie to the account's language, so
  the account wins on every browser.
- **One package for each:** only `packages/db` imports `drizzle-orm`
  and `pg`; only `packages/auth` imports `better-auth`; the shared
  ESLint config forbids them everywhere else (`no-restricted-imports`,
  turned off in those two packages), so lint fails any other import.
  pg-boss (spec 011) is allowed in `apps/server`: it takes its connection
  from `packages/db`'s `jobConnection()`, and joins a transaction through
  `jobDb(tx)`, so the server never imports `pg` itself.
- **No raw HTML:** `react/no-danger` is an error in the shared ESLint
  config; the one JSON-LD block disables it on its line, with the reason.

**End to end in CI:** an `e2e` job in `.github/workflows/ci.yml` runs
PostgreSQL as a service, the server with the fake Discord provider, the web
app with `next build && next start` and `SERVER_ORIGIN` pointing at the
server, then Playwright. Specs 008 and 009 add their tests to it.

Sign-in with Discord can't run in CI: the server tests replace Discord's
authorisation, token and profile endpoints with a local fake, through a
test-only provider configuration (the Discord provider's endpoint options
or Better Auth's generic OAuth plugin, whichever the pinned version
supports; task 6 checks), so the flow runs end to end without the network.

## Tasks

Owner tasks need the owner's accounts; the rest are code.

1. **Owner: Discord application.** In Discord's Developer Portal, create
   "Coachlore", add both redirect addresses, and keep the client ID and
   secret for the server's environment. Done when the IDs are in the local
   `apps/server/.env` and in a password manager.
2. **`packages/contracts`.** Zod (from the catalog), `problem`, `me` and
   `realtime` schemas, built and type-checked like the other packages.
   Done when lint, typecheck and a schema test pass.
3. **`apps/server` skeleton.** `buildApp`, `env` (Zod, refusing to start on
   a bad value), `errors`, health, shutdown, pino, Sentry, the tsconfig for
   type stripping, `compose.yaml`, the Turborepo tasks with their `env`, and
   CI running its tests. Done when `bun run dev` serves `/api/v1/health`
   locally, the Docker image starts with `node`, and tests 14 and 15 pass.
4. **`packages/db`.** The client, drizzle-kit config, `migrate()`, the
   schema folder, `startTestDb()`, the `db:seed` entry, and the lint rule that keeps the driver inside it. The server runs `migrate()` at
   start-up. Done when a test migrates an empty PostgreSQL, health reports
   `db: up`, and test 22 passes.
5. **The proxy and the origin guard.** The Route Handler in the web app
   (404 without `SERVER_ORIGIN`), the guard with secret rotation, the CSP
   and image changes, `proxy.ts` with the nonce CSP, and `react/no-danger`.
   Done when the web app reaches health through `/api/v1/health`, a direct
   request without the secret gets 403, and tests 13, 17 and 18 pass.
6. **`packages/auth` and sign-in.** `createAuth()` with Discord
   (`identify` only), database sessions, trusted origin, no IP or user
   agent, tokens cleared, `user.language`; the typed client; the server's
   auth plugin; the fake Discord for tests; rate limits. Done when tests 2,
   3, 4, 11 and 16 pass.
7. **`/sign-in` and the account menu.** Fixture screens first (spec 001's
   process), the owner's review, then the real flow. Done when the e2e test
   signs in against the fake and axe passes.
8. **`/me`: profile, language, export, delete, sign out.** With the
   blocker and anonymiser lists, and every string in both dictionaries.
   Done when tests 6, 7, 20 and 21 pass and the owner has reviewed the
   screen on a phone, in both languages.
9. **Real-time tickets.** Done when test 8 passes.
10. **Owner: the VM.** An Oracle Cloud account (choose the home region with
    care: Always Free resources live only there); an A1 VM with Ubuntu,
    2 OCPUs and 6 GB (see ADR 0006 on idle reclamation); Coolify
    installed; a DuckDNS name and a fallback name pointing at the VM; the
    security list open only on 22, 80 and 443; SSH by key only; unattended
